# FolderCreator 本地手动测试清单（v0.4.0 · 六项增强功能）

[English](FolderCreator-本地手动测试清单_EN.md) | [简体中文](FolderCreator-本地手动测试清单.md)

> 适用程序：`FolderCreator.exe`（WinToolBox 的文件夹批量创建工具，win-x64 免安装单文件）
> 适用系统：Windows 10 / 11
> 执行人：用户（本人在物理机上手动操作）
> 预计耗时：约 20 分钟（6 个核心轮次）

本清单验证本轮新增的 **6 项功能**：规则模板管理、反向生成规则、占位文件创建、多根目录批量创建、检查报告导出、目录树文本导出。
原有的「创建文件夹 / 检查一致性」（含严格 / 宽松模式）请继续参考 [UsbBackup 与 FolderCreator 通用验收](本地手动测试清单.md) 中的相关轮次。

---

## 0. 先记住三件事

1. **本工具会真实创建文件夹和文件**：请务必先在一个**专门的测试目录**里操作，不要拿重要目录试。
2. **占位文件只在“真正为空”的目录里创建**：即该目录既没有文件、也没有子目录。父目录一旦有了子目录就不会再加 `.gitkeep`。
3. **配置文件在用户目录**：模板保存在 `%AppData%\WinToolBox\FolderCreator\templates.json`，日志在 `%LocalAppData%\WinToolBox\logs\`。

## 1. 测试前准备

### 1.1 准备程序

- [ ] 从发布页下载 `FolderCreator-win-x64.zip`，解压到**桌面或其他非系统目录**（例如 `D:\Tools\FolderCreator\`）。
- [ ] **双击** `FolderCreator.exe` 启动；主界面应正常出现（标题：`FolderCreator - 批量创建文件夹`）。
- [ ] 记下界面结构，后面每一步都会用到：
  - 顶部工具栏：`模板：[下拉框]` `[保存为模板]` `[删除模板]` …… `[从现有目录生成规则]` `[导出检查报告]` `[导出目录树]`
  - 目标区：`根目录：[输入框] [浏览…]`、`[ ] 启用多根目录`、`[ ] 为空目录创建占位文件（.gitkeep）`
  - 中部：左侧规则输入框、右侧结果树
  - 下部：`检查模式`、`[创建文件夹] [检查一致性] [载入示例规则]`
  - 底部：`运行日志` 区 + 状态栏

### 1.2 准备测试目录

在 `D:\` 或桌面新建两个空目录，例如：

```text
D:\FCTest\项目A
D:\FCTest\项目B
```

### 1.3 路径速查

| 内容 | 路径 |
| --- | --- |
| 目录模板库 | `%AppData%\WinToolBox\FolderCreator\templates.json` |
| 运行日志 | `%LocalAppData%\WinToolBox\logs\wintoolbox-yyyyMMdd.log` |
| 导出的目录树 | 由你在保存对话框中选择（默认文件名 `目录树.txt`） |
| 导出的检查报告 | 由你在保存对话框中选择（默认文件名 `目录检查报告.md`） |

## 2. 测试轮次

> 通用节奏：填好根目录与规则 → 点对应按钮 → 看**结果树**（颜色与括号说明）与**运行日志** → 到资源管理器核对实际文件。

### 第 1 轮：规则模板管理（保存 / 载入 / 删除 / 内置模板）

**步骤**

1. 在规则框输入任意内容，例如：

   ```text
   # 测试模板
   -文档
   --图片
   ```

2. 在顶部「模板」下拉框里**直接输入** `我的测试模板`（下拉框可编辑），点 `[保存为模板]`。
3. 用记事本打开 `%AppData%\WinToolBox\FolderCreator\templates.json`。
4. 清空规则框，然后在「模板」下拉框里选择 `我的测试模板`。
5. 选择内置模板 `Web 项目`（弹窗确认覆盖）→ 再选择 `Python 项目`。
6. 选中 `我的测试模板`，点 `[删除模板]` → 确认。

**预期结果**

- [ ] 保存后状态栏出现「模板已保存：我的测试模板（新建）」。
- [ ] `templates.json` 里能看到该模板（形如 `"我的测试模板": "# 测试模板\r\n-文档\r\n--图片"`），**首次启动时会自动写入** `Web 项目`、`Python 项目` 两个内置模板。
- [ ] 选择模板后，规则框内容被替换成该模板内容。
- [ ] 选 `Web 项目` 时出现「是否覆盖当前规则内容」的确认框；选 `Python 项目` 同样。
- [ ] 删除后下拉框里不再有 `我的测试模板`，`templates.json` 中对应条目消失。

**判定**：4 项全部符合 → 通过。

---

### 第 2 轮：从现有目录反向生成规则

**步骤**

1. 用资源管理器在 `D:\FCTest\项目A` 下手动建出这样一棵树：

   ```text
   项目A\
   ├─.git\            （模拟版本库目录，应被默认排除）
   ├─node_modules\    （应被默认排除）
   ├─src\
   │  ├─components\
   │  └─pages\
   └─tests\
   ```

2. 在程序里把「根目录」设为 `D:\FCTest\项目A`。
3. 点 `[从现有目录生成规则]`（若规则框非空会先确认覆盖）。

**预期结果**

- [ ] 规则框里生成的内容**按名称排序**，且形如：

  ```text
  -src
  --components
  --pages
  -tests
  ```

- [ ] `.git` 与 `node_modules` **没有出现**（默认排除 `.git`、`node_modules`、`bin`、`obj`、`.vs`）。
- [ ] 状态栏显示「已生成规则：N 个目录」。
- [ ] 立刻再点一次 `[从现有目录生成规则]`，生成结果**完全一致**（可重复、结果稳定）。

**判定**：4 项全部符合 → 通过。

---

### 第 3 轮：为空目录创建占位文件

**步骤**

1. 勾选 `[√] 为空目录创建占位文件（.gitkeep）`。
2. 根目录设为 `D:\FCTest\项目A`（或另建一个空目录 `D:\FCTest\占位测试`），规则输入：

   ```text
   -文档
   --图片
   -源码
   --模块
   ```

3. 点 `[创建文件夹]`。

**预期结果**

- [ ] 资源管理器里：`文档\图片\.gitkeep` 与 `源码\模块\.gitkeep` 各出现一个 **0 字节**文件。
- [ ] **`文档` 与 `源码` 目录本身没有 `.gitkeep`**（它们已经有子目录，不算空目录）。
- [ ] 结果树上这些节点显示「（已创建）（已创建 .gitkeep）」。
- [ ] 再次点 `[创建文件夹]`：目录变成「已存在，已跳过」，`.gitkeep` **不会重复创建、也不会报错**。
- [ ] 取消勾选后再建一个空目录（例如 `-空目录`），结果里**不应**出现 `.gitkeep`。

**判定**：5 项全部符合 → 通过。

---

### 第 4 轮：多根目录批量创建

**步骤**

1. 勾选 `[√] 启用多根目录`：界面下方出现多行输入框，上方单根输入框变灰。
2. 在多行框里输入（**第 3 行故意与第 1 行大小写不同，用于验证去重**）：

   ```text
   D:\FCTest\项目A
   D:\FCTest\项目B
   D:\FCTest\项目A
   ```

   > 顺带试试非法路径：再加一行 `D:\FCTest\非法|路径`。
3. 规则输入：

   ```text
   -文档
   --图片
   -源码
   ```

4. 点 `[创建文件夹]`，过程中观察状态栏与进度条。

**预期结果**

- [ ] 状态栏在创建过程中显示「**当前处理第 1 / 共 2 个**：…」→「第 2 / 共 2 个」，进度条随之推进到 100%。
- [ ] 结果树出现 **2 个根节点**，分别标注「第 1 / 2 个根目录：…」「第 2 / 2 个根目录：…」，各自挂着自己的目录明细。
- [ ] `项目A` 与 `项目B` **都被创建**了同样的结构（重复行与非法行被忽略）。
- [ ] 状态栏/日志提示「已忽略 N 个无效或重复的路径」。
- [ ] **容错验证**：把 `项目B` 删掉后用一个**已存在的同名文件**占位（例如在 `D:\FCTest\` 下建一个无扩展名文件叫 `项目B`），再执行一次 → 该根目录报失败，**另一个根目录仍然正常创建**（单点失败不中断整体）。

**判定**：5 项全部符合 → 通过。

---

### 第 5 轮：检查报告导出（Markdown）

**步骤**

1. 用一个**故意不一致**的目录验证（例如 `D:\FCTest\项目A` 里手动删掉 `源码\模块`，再新建一个规则里没有的 `多余目录`）。
2. 根目录设为该目录，规则填：

   ```text
   -文档
   --图片
   -源码
   --模块
   ```

3. 选 `严格模式（检查多余文件夹）`，点 `[检查一致性]`。
4. 点 `[导出检查报告]`，在保存对话框里存为 `检查报告.md`（建议存到桌面）。
5. 用记事本或 VS Code 打开这份报告。

**预期结果**

- [ ] 检查前 `[导出检查报告]` 是**灰的（不可点）**；检查成功后变为**可点**。
- [ ] 结果树用颜色区分：绿色=匹配、红色=缺失、**黄褐色=多余**，并**同时**出现「模块（缺失）」与「多余目录（多余）」。
- [ ] 报告包含：标题、检查时间、目标目录、检查模式、检查结论（存在差异）、统计表（匹配 / 缺失 / 多余 / 合计）。
- [ ] 报告按分类列出明细：`## 缺失的文件夹（1）` → `- 源码\模块`；`## 多余的文件夹（1）` → `- 多余目录`；`## 匹配的文件夹（3）`。
- [ ] 报告里的中文与路径显示正常（UTF-8），路径中的反斜杠在 Markdown 预览里显示为单个 `\`。
- [ ] 缺失/多余**超过 100 条**时，对应小节会被折叠成 `<details>…</details>`（可用脚本批量建 120 个多余目录验证）。

**判定**：6 项全部符合 → 通过。

---

### 第 6 轮：目录树文本导出

**步骤**

1. 根目录设为 `D:\FCTest\项目A`（用它现有的结构即可）。
2. 点 `[导出目录树]`，保存为 `目录树.txt`。
3. 用记事本打开。

**预期结果**

- [ ] 第一行是根目录的完整路径。
- [ ] 后面是标准 `tree` 风格的树形文本，例如：

  ```text
  D:\FCTest\项目A
  ├─src
  │  ├─components
  │  └─pages
  └─tests
  ```

- [ ] 使用 `├─` / `└─` / `│` 字符，**中文与缩进对齐正常**。
- [ ] 末尾有一行统计，形如 `3 个目录`。
- [ ] `.git`、`node_modules`、`bin`、`obj`、`.vs` **没有出现**（默认排除）。
- [ ] 再导出一次，内容与上次**完全一致**（稳定可重复）。

**判定**：5 项全部符合 → 通过。

## 4. 失败时该收集什么信息

1. **运行日志**：界面底部「运行日志」区的内容，或日志文件 `%LocalAppData%\WinToolBox\logs\wintoolbox-yyyyMMdd.log` 当天的记录（其中会写明失败的目录与原因）。
2. **模板库**：`%AppData%\WinToolBox\FolderCreator\templates.json` 的内容（模板相关问题时）。
3. **操作复现步骤**：点了哪个按钮、根目录与规则的**原文**（尤其是是否勾选了「多根目录」「占位文件」）。
4. **界面截图**：结果树 + 状态栏 + 运行日志三处。
5. **实际磁盘结果**：在资源管理器里对该目录执行一次「显示 → 隐藏的项目」后截图。

## 5. 说明

- 全部 6 项功能的**核心逻辑**（模板读写、规则生成、占位文件、多根目录去重与容错、报告与目录树文本生成）都有**单元测试**覆盖，共 322 个测试用例；本清单用于验证**界面交互与真实磁盘结果**。
- 本清单基于**独立 FolderCreator 项目**（`src/Tools/FolderCreator/`）编写，未引入任何主程序（`WinToolBox.App`）依赖。
