# FileMaster 使用说明

[English](README_EN.md) | [简体中文](README.md)

> WinToolBox 子工具（原 **FolderCreator** 重命名并扩展而来）：既可以用一段「短横线缩进」文本**批量创建文件夹结构**、**检查现有目录是否符合规则**，也提供 **8 项文件 / 文件夹管理功能**。

[← 返回 WinToolBox 总览](../../../README.md)

- 程序名：`FileMaster.exe`（WinForms 桌面程序，C# / .NET 8）
- 项目位置：`src/Tools/FileMaster/`，引用共享库 `src/WinToolBox.Core` 并复用其中的 `Logger`、`HashEngine`
- 原有 FolderCreator 的功能**全部保留**；旧版模板会在首次启动时从 `%AppData%\WinToolBox\FolderCreator\` 自动迁移到 `%AppData%\WinToolBox\FileMaster\`

## 运行要求

| 使用方式 | 要求 |
| --- | --- |
| 源码运行 | Windows 10 / 11（x64）+ .NET 8 SDK |
| 单文件 exe | Windows 10 / 11（x64），双击 `FileMaster.exe` 即可；发布包自包含 .NET 运行时，**免安装、无需预装 .NET** |

下载：打开 <https://github.com/zhuyuebin/WinToolBox/releases/latest>，下载 **`FileMaster-win-x64.zip`**，解压到任意目录后双击其中的 `FileMaster.exe`。

## 快速上手（5 步）

1. **启动**：运行 `FileMaster.exe`；从源码调试则执行 `dotnet run --project src/Tools/FileMaster/FileMaster.csproj`。
2. **选根目录**：在顶部文本框填写目标目录，或点「浏览…」选择——所有文件夹都会创建在这个根目录下。
3. **粘贴规则**：在左侧规则框粘贴短横线层级文本；不确定格式时点「载入示例规则」填入一份可直接运行的示例。
4. **选模式**：检查时选择 **严格模式**（默认，会报出「多余」）或 **宽松模式**（只报「缺失」）。
5. **执行**：「创建文件夹」开始批量创建，「检查一致性」对比目标目录；结果显示在右侧结果树，进度与提示显示在底部状态栏。

## 文件管理功能（8 项）

全部功能都在主窗口菜单 **「文件管理(F)」** 中，每个功能打开独立窗口，互不影响；窗口内统一提供：顶部输入区、中部预览列表、底部按钮 + 运行日志 + 状态栏/进度条，耗时操作都在后台线程执行且可取消。

| # | 功能 | 说明 | 安全策略 |
| --- | --- | --- | --- |
| 1 | **批量重命名（文件 / 文件夹）** | 「处理对象」可选文件 / 文件夹 / 两者；规则支持删除字符、查找替换（文本或正则，支持 `$1` 分组）、前缀、后缀、序号（起始值 / 位数 / 分隔符 / 位置）、日期（格式 + 取值来源）、统一扩展名；默认保护扩展名 | 先「预览」标记冲突（目标已存在 / 预览内重名），只有可执行项会被重命名；执行前二次确认 |
| 2 | **空文件夹清理** | 扫描「自身及所有子目录中都没有文件」的目录（只含空子目录也算空），可选择只扫描直接子目录；删除时先删深层目录 | 结果默认全选但仍需点「删除选中」并二次确认；默认**删除到回收站**，「永久删除」另需确认 |
| 3 | **时间戳批量修改** | 模式一「修改时间 = 创建时间」；模式二「统一改成指定时间」（可分别勾选创建 / 修改 / 访问时间）；支持文件 / 文件夹 / 两者与递归 | 先预览（显示新旧时间），确认后执行；目录在子项之后写入，避免被覆盖 |
| 4 | **批量移动 / 自动分类** | 规则文本每行「类型\|参数\|目标子目录」：`扩展名\|.jpg;.png\|图片`、`日期\|yyyy-MM\|按日期`、`首字母\|\|按首字母`、`其它\|\|其它`（兜底）；可移动或复制 | 先预览（冲突检测：目标同名且未勾选覆盖则跳过），二次确认后执行；可顺带清理源目录空文件夹 |
| 5 | **文件夹差异比对** | 左右目录比对，三种比较方式：大小 + 修改时间（默认）、仅大小、SHA256 哈希；支持忽略名称与时间容差 | 只读操作，不改动任何文件；可导出文本报告 |
| 6 | **重复文件查找** | 先按大小分组，再对候选文件计算 MD5 / SHA1 / SHA256（默认 SHA256），按内容分组展示；可设置最小文件大小与忽略名称 | 每组默认保留修改时间最早的一份（不勾选），其余默认勾选；删除前二次确认，**默认删除到回收站** |
| 7 | **文件夹同步 / 镜像** | 单向复制（不动目标多余内容）/ 单向同步（删除目标多余内容）/ 镜像（目标完全等于源）；可选「用哈希比较内容」 | 先生成计划预览（删除红色、复制绿色、建目录灰蓝），二次确认后执行；删除默认走回收站；源 / 目标相同或互相包含时直接拒绝 |
| 8 | **文件占用解锁** | 使用 Windows **Restart Manager** 查询占用文件（或文件夹内文件）的进程：PID、进程名、类型、是否可重启 | 只查询不修改；结束进程前二次确认，「关键系统进程」一律拒绝结束；**不读写注册表** |

> 8 项功能的逐项验收步骤见[《FileMaster 本地手动测试清单》](../../../docs/testing/FileMaster-本地手动测试清单.md)。

## 规则语法

用行首连续的 `-` 表示层级：1 个 `-` 为第一级，`--` 为第二级，`---` 为第三级，以此类推。

```text
# 这是一个注释行，以 # 开头将被忽略
根目录名称

-一级目录
--二级目录
---三级目录
-一级目录2
--二级目录2
```

解析规则：

| # | 规则 | 说明 |
| --- | --- | --- |
| 1 | `-` 的个数 = 层级深度 | 1 个 `-` 为第一级，`--` 为第二级，最多 32 级 |
| 2 | 短横线后的空格可省略 | `-一级目录` 与 `- 一级目录` 等价，前导空格会被去掉 |
| 3 | `#` 开头的行为注释 | 整行忽略，可写说明文字 |
| 4 | 行首没有 `-` 且不是 `#` 的行被忽略 | 例如 `根目录名称`，可当作根目录提示书写，不参与创建 |

上面的示例会创建：`一级目录\二级目录\三级目录` 与 `一级目录2\二级目录2`。

## 父级自动补齐与名称校验

- **父级自动补齐**：如果出现 `---三级目录` 而前面没有 `--二级目录`，解析器会**自动补齐缺失的父级**，补齐出来的目录名固定为 **`未命名目录`**，并在界面上给出**带行号的警告**。请按警告提示回到规则里把 `未命名目录` 改成你想要的名称。
- **非法字符校验**：目录名不能包含以下内容，否则解析阶段直接报错并列出「第 N 行」，此时**不会执行创建**：
  - 非法字符：`\`、`/`、`:`、`*`、`?`、`"`、`<`、`>`、`|`
  - Windows 保留设备名：`CON`、`PRN`、`AUX`、`NUL`、`COM1`~`COM9`、`LPT1`~`LPT9`
  - 目录名不能以 `.` 或空格结尾
  - 单个层级最长 255 个字符，层级最深 32 级

## 创建文件夹

- 在所选根目录下用 `Directory.CreateDirectory` 递归创建，**父级目录自动创建**。
- **已存在的文件夹直接跳过、不报错**，只创建缺失的部分，可重复执行。
- 创建过程在**后台线程**执行，界面不会卡死，底部有进度条与状态提示。
- 失败**逐条捕获**：权限不足、路径过长、非法字符等都会给出友好提示，失败项在结果树中标红，其余目录继续创建。

## 检查一致性

选择目标根目录后点「检查一致性」，结果用树形结构展示并着色：

| 状态 | 含义 | 颜色 |
| --- | --- | --- |
| **匹配** | 规则里有，目标目录里也有 | 绿色 |
| **缺失** | 规则里有，目标目录里没有（创建失败同样标红） | 红色 |
| **多余** | 目标目录里有，规则里没有（仅严格模式） | 黄色 |
| **已存在（跳过）** | 创建时目录已存在，直接跳过 | 灰色 |

| 检查模式 | 行为 |
| --- | --- |
| **严格模式**（默认） | 除「匹配 / 缺失」外，还报出目标目录里多出的文件夹（「多余」） |
| **宽松模式** | 只检查规则要求的文件夹是否存在，忽略多出的文件夹 |

## 日志

FileMaster 复用 WinToolBox 共享日志组件，日志写入：

```text
%LocalAppData%\WinToolBox\logs\wintoolbox-yyyyMMdd.log
```

（通常为 `C:\Users\<用户名>\AppData\Local\WinToolBox\logs\`，与 UsbBackup 共用同一日志文件，按天切割。）

## 常见问题

| 问题 | 原因与处理 |
| --- | --- |
| 为什么我的某一行没有被创建？ | 该行**行首没有 `-`**（会被当成根目录提示忽略）或**以 `#` 开头**（注释行）。请给需要创建的行加上对应数量的 `-`。 |
| 为什么出现了 `未命名目录`？ | 规则里跳级了（例如直接写 `---三级目录` 而缺少 `--二级目录`），解析器自动补齐父级，补齐出来的名字就是 `未命名目录`。按警告的行号把父级补全即可。 |
| 检查报了一堆「多余」怎么办？ | 目标目录里存在规则未描述的文件夹。若这些文件夹是正常的，改用**宽松模式**只检查缺失；若确实不该存在，到目标目录中删除后重新检查。 |
| 创建时报权限不足 / 路径过长？ | 换一个当前用户有写权限的根目录，或缩短目标路径（Windows 默认路径长度上限约 260 个字符）；失败原因会逐条显示在结果树与状态栏，并写入日志。 |
| 删除的文件去哪了？ | 默认全部**移入回收站**（可从回收站还原）。只有显式选择「永久删除」并确认后才会真正删除。 |
| 为什么「文件占用解锁」查不到任何进程？ | 该功能基于系统 Restart Manager：若进程以独占方式打开文件，通常能查到；被内存映射或某些内核态占用可能查不到。另外在受限沙箱中 Restart Manager 不可用，会给出明确的错误提示。 |
| 结束进程有风险吗？ | 有：目标程序未保存的数据会丢失。因此程序会在结束前二次确认，并**拒绝结束关键系统进程**（如 `System`、`lsass`、`csrss`、`svchost` 等）。 |
| 同步 / 镜像会不会误删源文件？ | 不会。程序在生成计划前会拒绝「源与目标相同」或「互相包含」的目录组合；删除只发生在目标目录，且默认走回收站并需二次确认。 |
