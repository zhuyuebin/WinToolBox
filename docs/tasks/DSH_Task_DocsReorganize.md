# DSH 任务书：WinToolBox 仓库 Markdown 文档整理

## 0. 前置说明
你是在全新对话中执行，没有历史上下文。本任务只涉及**文档文件的移动、重命名、链接更新**，**不修改任何源码、配置文件、.csproj、.sln、CI 脚本**。

仓库：WinToolBox（https://github.com/zhuyuebin/WinToolBox）
技术栈：C# (.NET 8) + WinForms + xUnit
工具：FileMaster、UsbBackup

## 1. 任务目标
当前仓库的 Markdown 文档散落在根目录、`MD-files/`、各工具目录下，命名与存放位置混乱。请按下列规范统一整理：

### 目标结构
```
WinToolBox/
├─ README.md                    # 保留：中文主 README
├─ README_EN.md                 # 保留：英文主 README
├─ LICENSE                      # 保留
├─ CHANGELOG.md                 # 可选：若存在则保留，若不存在不新建
├─ docs/
│  ├─ README.md                 # 文档总索引（需新建或整理）
│  ├─ audit/                    # 审计报告
│  ├─ reports/                  # 修复报告、其他技术报告
│  ├─ testing/                  # 手动测试清单（中英）
│  ├─ tasks/                    # DSH 任务书（历史归档）
│  ├─ guides/                   # 用户指南、使用文档（若有）
│  └─ archive/                  # 已废弃/历史归档
├─ src/

│  │  ├─ README.md              # 保留原位（模块级文档）

│     ├─ FileMaster/

│        └─ README_EN.md        # 保留原位
└─ MD-files/                    # 整理后删除该目录（内容已迁走）
```

### 归类规则
| 文档类型 | 目标位置 | 命名规则 |
|---|---|---|
| 审计报告（AUDIT_REPORT 等） | `docs/audit/` | 保持原名，若多份则加日期前缀 `YYYY-MM-DD-xxx.md` |
| 修复报告、技术报告（FIX_REPORT 等） | `docs/reports/` | 同上 |
| 手动测试清单（中英） | `docs/testing/` | `FileMaster-本地手动测试清单.md` / `.en.md` |
| DSH 任务书（DSH_Task_*.md） | `docs/tasks/` | 保持原名，去掉多余的 `.md.md` |
| 用户指南、使用手册 | `docs/guides/` | 保持原名 |
| 历史废弃文档 | `docs/archive/` | 保持原名 |
| 模块级 README | 保留在各自模块目录下 | 不移动 |
| 根目录 README / README_EN / LICENSE / CHANGELOG | 保留在根目录 | 不移动 |

## 2. 执行步骤

### 步骤 1：扫描并列出现状清单
先执行扫描，**不要移动任何文件**：
1. 用 `git ls-files "*.md"` 列出所有被跟踪的 Markdown 文件。
2. 用文件系统遍历列出所有 `.md` 文件（含未被跟踪的）。
3. 对每个文件，输出：**当前路径**、**文件大小**、**首行标题**、**建议归类**（按第 1 节规则）。
4. 检查是否存在以下问题并单列：
   - 文件名以 `.md.md` 结尾（重复扩展名）
   - 文件名含拼写错误（如用户名、路径拼错）
   - 同一内容存在多个副本
   - 内容已过期（如仍写 `FolderCreator`、旧路径）
   - 空文件或占位文件

**输出格式**：
```markdown
## 现状扫描结果
### 建议保留原位（不动）
- 路径1
- 路径2
### 建议移动到 docs/audit/
- 路径 → 目标路径
### 建议移动到 docs/reports/
...
### 建议删除（重复/空文件）
- 路径 → 理由
### 需要用户决策
- 路径 → 原因
```

**扫描完成后停下来，把结果发给用户确认。不要继续执行步骤 2。**

### 步骤 2：执行移动（用户确认后）
1. 使用 `git mv` 保留文件历史：
   ```
   git mv 原路径 目标路径
   ```
2. 对于新建的 `docs/` 子目录，先 `mkdir`。
3. 移动后立即验证文件确实在目标位置。
4. 遇到命名冲突（目标位置已有同名文件）时停下来报告用户，不要覆盖。

### 步骤 3：更新所有引用链接
移动完成后，**全仓库搜索**所有指向被移动文件的引用，并更新路径：
1. 搜索所有 `.md` 文件中的相对链接：`\[.*\]\(.*\.md.*\)`
2. 搜索 `README.md`、`README_EN.md` 中的文档索引
3. 搜索 `.csproj`、`.sln`、`publish-local.ps1`、`.github/workflows/*.yml` 中是否引用了被移动的 MD 文件（大概率没有，但要确认）
4. 搜索源码注释中引用了 MD 文件路径的地方（如 `// 详见 docs/...`）

更新后，**逐条验证链接目标存在**：
```powershell
# 示例：对 README.md 中所有相对链接做存在性校验
```

### 步骤 4：创建/整理 docs/README.md 索引
在 `docs/README.md` 中创建一份文档索引，包含：
- 项目文档总览
- 各子目录说明
- 常用文档的直达链接（审计报告、修复报告、手动测试清单）
- 归档说明（历史任务书已归档，路径与 URL 可能过期）

### 步骤 5：清理 MD-files/
确认 `MD-files/` 内所有文档已迁移、所有引用已更新后：
1. 检查 `MD-files/` 是否为空。
2. 若为空，删除目录。
3. 若不为空，报告剩余文件给用户。
4. 检查 `.gitignore` 中是否有针对 `MD-files/` 的规则，若有则一并清理（只删该规则，不动其他）。

### 步骤 6：最终验证
1. 全仓库 `git status` 应显示大量 rename（而不是 delete + add）。
2. 所有 Markdown 相对链接通过存在性校验（0 条失效）。
3. 运行 `dotnet build WinToolBox.sln -c Release` 确认构建不受影响（应该不受影响，因为只动了 MD 文件）。
4. 报告：
   - 移动了多少文件
   - 更新了多少处链接
   - 有多少文件被删除（重复/空文件）
   - 是否有需要用户决策的遗留项

## 3. 命名规范要求

### 文件命名
- 全小写或全大写统一，不要混用（中文文档可保留中文名，英文文档用小写）
- 用 `-` 而不是 `_` 或空格
- 不要出现 `.md.md` 双扩展名
- 报告类文档建议加日期前缀 `YYYY-MM-DD-xxx.md`
- 中英对照文档用 `.en.md` 或 `_EN.md` 后缀，**全文统一用一种**

### 目录命名
- 全小写，用 `-` 连接
- 复数形式（`docs/audit/` 而非 `docs/audits/` 也行，但全文统一）

## 4. 约束与禁止

1. **只移动、不删除内容**：除非是重复副本或空文件，且必须先在步骤 1 列出、用户确认。
2. **不修改任何源码、csproj、sln、CI 脚本、publish-local.ps1**（除步骤 3 中需要更新 MD 引用外）。
3. **不修改 `.gitignore`**（除步骤 5 中清理 `MD-files/` 相关规则外）。
4. **不执行 git commit / git push**，只做 `git mv`。
5. **遇到不确定的归类，停下来问用户**，不要自行决定。
6. **不要批量重命名工具源码里的 README**（模块级 README 保留原位）。
7. **不新建 CHANGELOG.md**，除非根目录已存在。
8. **不要删除 `LICENSE`**，它不是 Markdown，但属于根目录必留文件。

## 5. 输出要求
最终输出一份 `DOCS_REORG_REPORT.md`，包含：
1. 扫描结果（步骤 1 的清单）
2. 实际执行的移动操作（`git mv` 命令清单）
3. 更新的链接清单（文件 + 行号）
4. 删除的文件清单及理由
5. 最终目录结构（`tree docs/` 的输出）
6. 未完成项与遗留问题
