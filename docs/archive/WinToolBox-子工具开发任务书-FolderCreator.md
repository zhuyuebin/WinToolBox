## 3. 核心功能详细说明

### 3.1 规则输入格式（重点）
用户使用“短横线缩进”文本表示文件夹层级，例如：
```text
# 这是一个注释行，以 # 开头将被忽略
根目录名称

-一级目录
--二级目录
---三级目录
-一级目录2
--二级目录2
```

**解析规则：**
1. 行首连续的 `-` 数量代表层级深度。1 个 `-` 为第一级，2 个 `--` 为第二级，以此类推。
2. 短横线后允许有空格，也允许直接跟目录名。解析时需去除短横线后的前导空格。
3. 行首没有 `-` 且不以 `#` 开头的行，视为注释或根目录提示，不参与创建。以 `#` 开头的行强制视为注释。
4. 如果出现 `---三级目录` 但前面没有 `--二级目录`，解析器应自动补齐缺失的父级目录（例如自动创建 `--二级目录` 和 `-一级目录`，或者抛出友好的格式错误提示，推荐自动补齐父级以保证创建逻辑正确）。
5. 文件夹名称不能包含 Windows 非法字符 `\ / : * ? " < > |`，解析时必须校验并提示用户。

### 3.2 文件夹生成逻辑
- 用户选择“根目录”路径。
- 根据解析出的层级结构，在根目录下批量创建文件夹。
- 使用 `Directory.CreateDirectory` 自动递归创建父级。
- 创建过程中需显示进度，不得阻塞 UI 线程（使用 `async/await` 或 `Task.Run`）。
- 如果目标文件夹已存在，跳过，不报错。

### 3.3 文件夹检查逻辑
- 用户选择“目标根目录”，点击检查。
- 检查模式：
  - **严格模式（默认）**：目标目录中多出的文件夹也要报出来，标记为“多余”。
  - **宽松模式**：只检查规则中要求的文件夹是否存在，不关心多出的文件夹。
- 检查结果输出：
  - **匹配**：规则有，目标也有。
  - **缺失**：规则有，目标没有。
  - **多余**：目标有，规则没有（仅严格模式）。
- 结果在界面上用树状结构或列表展示，用颜色区分：绿色=匹配，红色=缺失，黄色=多余。

## 4. UI 界面要求
- 使用 WinForms。
- 主界面布局建议：
  - 顶部：选择根目录的文本框 + “浏览”按钮。
  - 左侧：多行文本框，用于输入规则（带占位符提示）。
  - 中间：按钮区 —— “创建文件夹”、“检查一致性”。
  - 右侧/底部：结果展示区（TreeView 或 ListView），展示创建结果或检查结果。
  - 底部：状态栏，显示日志或操作结果。
- 检查模式切换：界面上提供单选按钮或复选框：`严格模式（检查多余）` / `宽松模式（仅检查缺失）`。
- 所有耗时操作必须使用后台线程，避免界面卡死。

- 编写 `RuleParser` 的单元测试：

  - 正确忽略 `#` 注释行和无 `-` 的普通行。
  - 正确识别非法字符并抛出异常或返回错误。
  - 缺失父级时，测试自动补齐逻辑。
- 编写 `FolderGenerator` 的单元测试：

- 编写 `FolderChecker` 的单元测试：
  - 严格模式下，正确识别缺失和多余。
  - 宽松模式下，只识别缺失，忽略多余。
- 所有测试必须能在本地通过 `dotnet test`。
